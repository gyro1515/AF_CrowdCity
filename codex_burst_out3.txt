- follower shadow casting은 끄지만([Human.cs:54](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Human/Scripts/Human.cs:54)), receive shadow/light probe 비용은 prefab에 남아 있습니다([Human.prefab:618](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Human/Resources/Human/Human.prefab:618)).

권고 렌더 경로는 **BRG + 저폴리 multi-LOD VAT + 직접 culling**입니다.

- BRG는 URP 및 Android GLES3.x/Vulkan, iOS를 지원하지만 culling과 DOTS-instancing 호환 shader를 직접 구현해야 합니다([BRG 호환성과 제약](https://docs.unity3d.com/6000.3/Documentation/Manual/batch-renderer-group-how.html)).

정확한 draw call·메모리 대역폭·지속 발열 한계는 **확인 불가(실기기 프로파일 필요)**입니다.

## 4. 결정성

**동일 빌드·동일 플랫폼에서 동일 입력 재실행의 bit-identical 계약은 유지할 수 있습니다.** 다만 다음 둘은 자동 보장되지 않습니다.

- 기존 managed/CharacterController 오라클과 새 Burst 경로의 byte-for-byte 동일성
- Android/iOS 또는 서로 다른 ARM CPU 간 cross-ISA bit-identical

현재 오라클도 같은 환경에서 생성한 두 binary만 비교합니다([CrowdOracleHarness.cs:271](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Game/Editor/CrowdOracleHarness.cs:271), [CrowdOracleHarness.cs:304](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Game/Editor/CrowdOracleHarness.cs:304)). 설계 계약 역시 cross-run replay를 주장하지 않습니다([DESIGN.md:66](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Docs/CrowdCity/DESIGN.md:66)).

유지 조건:

- Burst Job에 `FloatMode.Strict`, `FloatPrecision.Standard`; Fast math 금지. Burst/Unity/빌드 타깃을 고정.
- Grid는 atomic append 금지. `(cellKey, stable AgentId)` 정렬 또는 deterministic prefix-sum scatter 사용. 현재 grid의 삽입·열거 순서도 결과 누산에 영향을 줍니다([SpatialGrid.cs:91](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Crowd/Core/SpatialGrid.cs:91), [CrowdRoot.cs:914](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Crowd/Scripts/CrowdRoot.cs:914)).
- Recruit는 `(distance², claimantId)` 최소값을 구한 뒤 stable AgentId 순서로 commit. 현재도 낮은 ID tie-break가 있습니다([RecruitResolver.cs:75](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Crowd/Core/RecruitResolver.cs:75)).
- Combat은 worker-local 결과 후 pair/victim을 canonical key로 정렬하고 단일 순서로 commit. 현재 victim 거리/ID 정렬을 보존해야 합니다([CombatResolver.cs:545](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Crowd/Core/CombatResolver.cs:545)).
- 현재 전역 `System.Random`의 가변 draw를 병렬 소비하면 안 됩니다([CrowdRoot.cs:253](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Crowd/Scripts/CrowdRoot.cs:253), [CrowdRoot.cs:1037](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Crowd/Scripts/CrowdRoot.cs:1037)).
  - 기존 오라클 유지: main thread에서 기존 ID 순으로 RNG 값을 미리 생성.
  - 새 계약: `(seed, AgentId, RNG-domain, counter)` 기반 스트림으로 바꾸고 오라클을 명시적으로 re-baseline.

- cross-device bit 동일성이 정말 필요하면 float strict만으로 부족하며 fixed-point 또는 명시적 양자화가 필요합니다.

## 3. 모바일 렌더링

시뮬레이션 선택과 무관하게 **bulk 렌더 경로 교체는 필수**입니다.

- `BatchRendererGroup`, `RenderMeshIndirect`, `DrawMeshInstanced`, `LODGroup` 사용은 저장소 `rg` 결과 0건입니다.
- Unity는 SkinnedMeshRenderer의 GPU instancing을 지원하지 않습니다([Unity GPU instancing](https://docs.unity3d.com/6000.3/Documentation/Manual/gpu-instancing-enable.html)).
- 팀 material도 instancing이 꺼져 있습니다([Team_Neutral.mat:10](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Human/Materials/Team_Neutral.mat:10)).
- follower shadow casting은 끄지만([Human.cs:54](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Human/Scripts/Human.cs:54)), receive shadow/light probe 비용은 prefab에 남아 있습니다([Human.prefab:618](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Human/Resources/Human/Human.prefab:618)).

권고 렌더 경로는 **BRG + 저폴리 multi-LOD VAT + 직접 culling**입니다.

- BRG는 URP 및 Android GLES3.x/Vulkan, iOS를 지원하지만 culling과 DOTS-instancing 호환 shader를 직접 구현해야 합니다([BRG 호환성과 제약](https://docs.unity3d.com/6000.3/Documentation/Manual/batch-renderer-group-how.html)).
- `RenderMeshIndirect`는 compute shader 지원이 필요하고 하나의 `worldBounds` 단위로 cull/sort됩니다([RenderMeshIndirect](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Graphics.RenderMeshIndirect.html)). 현재 프로젝트는 GLES 3.1을 강제하지 않으므로([ProjectSettings.asset:531](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/ProjectSettings/ProjectSettings.asset:531)), Vulkan/Metal/GLES3.1 상위 tier 최적화로 두는 편이 안전합니다.
- VAT는 Animator·bone Transform·runtime skinning을 제거하지만, visible agent×vertex×VAT texture fetch 비용은 그대로입니다. 저폴리 LOD, 거리별 animation sampling, frustum/occlusion culling 없이는 VAT만으로 부족합니다.
- bulk population에서는 Animator·SkinnedMeshRenderer·41 bone Transform 제거가 필수입니다. 카메라/HUD용 소수 leader proxy는 기존 GameObject로 유지할 수 있습니다.

정확한 draw call·메모리 대역폭·지속 발열 한계는 **확인 불가(실기기 프로파일 필요)**입니다.

## 4. 결정성

**동일 빌드·동일 플랫폼에서 동일 입력 재실행의 bit-identical 계약은 유지할 수 있습니다.** 다만 다음 둘은 자동 보장되지 않습니다.

- 기존 managed/CharacterController 오라클과 새 Burst 경로의 byte-for-byte 동일성
- Android/iOS 또는 서로 다른 ARM CPU 간 cross-ISA bit-identical

현재 오라클도 같은 환경에서 생성한 두 binary만 비교합니다([CrowdOracleHarness.cs:271](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Game/Editor/CrowdOracleHarness.cs:271), [CrowdOracleHarness.cs:304](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Game/Editor/CrowdOracleHarness.cs:304)). 설계 계약 역시 cross-run replay를 주장하지 않습니다([DESIGN.md:66](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Docs/CrowdCity/DESIGN.md:66)).

유지 조건:

- Burst Job에 `FloatMode.Strict`, `FloatPrecision.Standard`; Fast math 금지. Burst/Unity/빌드 타깃을 고정.
- Grid는 atomic append 금지. `(cellKey, stable AgentId)` 정렬 또는 deterministic prefix-sum scatter 사용. 현재 grid의 삽입·열거 순서도 결과 누산에 영향을 줍니다([SpatialGrid.cs:91](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Crowd/Core/SpatialGrid.cs:91), [CrowdRoot.cs:914](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Crowd/Scripts/CrowdRoot.cs:914)).
- Recruit는 `(distance², claimantId)` 최소값을 구한 뒤 stable AgentId 순서로 commit. 현재도 낮은 ID tie-break가 있습니다([RecruitResolver.cs:75](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Crowd/Core/RecruitResolver.cs:75)).
- Combat은 worker-local 결과 후 pair/victim을 canonical key로 정렬하고 단일 순서로 commit. 현재 victim 거리/ID 정렬을 보존해야 합니다([CombatResolver.cs:545](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Crowd/Core/CombatResolver.cs:545)).
- 현재 전역 `System.Random`의 가변 draw를 병렬 소비하면 안 됩니다([CrowdRoot.cs:253](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Crowd/Scripts/CrowdRoot.cs:253), [CrowdRoot.cs:1037](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Crowd/Scripts/CrowdRoot.cs:1037)).
  - 기존 오라클 유지: main thread에서 기존 ID 순으로 RNG 값을 미리 생성.
  - 새 계약: `(seed, AgentId, RNG-domain, counter)` 기반 스트림으로 바꾸고 오라클을 명시적으로 re-baseline.
- worker 수와 Job batch size를 바꿔도 동일 결과인지 검증해야 합니다.
- cross-device bit 동일성이 정말 필요하면 float strict만으로 부족하며 fixed-point 또는 명시적 양자화가 필요합니다.

## 5. 최소 변경 로드맵

| 단계 | 변경 | 검증 게이트 |
|---|---|---|
| M0: 2,000 기준선 | Release IL2CPP 실기기 프로파일, binary·RNG·event transcript 보존 | 목표 FPS의 CPU/GPU p95, steady-state 무할당, 최소 10분 thermal, 동일 seed 반복 |
| M1: data authority | AgentBuffer를 Persistent NativeArray SoA로 이식. 기존 GO adapter를 남겨 old/new A/B | 1,000 tick 반복 동일성, team/event 일치, 궤적·벽 관통·속도 분포 및 체감 비교 |
| M2: deterministic jobs | 이동/SDF/steering을 `IJobParallelFor`; grid/recruit/combat은 parallel map + canonical commit | worker/batch 변경 동일성, permutation test, 다중 seed transcript |
| M3: GPU presentation | bulk Human/CC/Animator/SMR 제거, BRG+VAT+LOD+culling 도입 | 2천 old/new 화면 A/B, draw submission·GPU p95·메모리·열, animation 이질감 |
| M4: scale ladder | 10k→20k→30k→50k 단계 상승 | 각 단계에서 CPU/GPU/GC/thermal/결정성/시각 gate를 모두 통과. 실패 시 다음 단계 금지 |

현재 tick은 0.02초, 프레임당 최대 4회입니다([GameplayRoot.cs:12](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Game/Scripts/GameplayRoot.cs:12), [GameplayRoot.cs:172](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/Assets/@Project/Game/Scripts/GameplayRoot.cs:172)). 이를 낮추거나 time-slicing하면 성능 최적화가 아니라 gameplay/oracle 계약 변경이므로 별도 피벗으로 처리해야 합니다.

규약 충돌은 다음과 같습니다.

- §0.2와 Native Job 도입은 실제 1만~5만 요구가 발생했으므로 정합합니다.
- M1의 CC/Transform 권위 변경과 M3의 per-agent prefab 제거는 §11.5의 prefab-per-agent mediator 트리와 충돌합니다([CLAUDE.md:265](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/CLAUDE.md:265)).
- 구현 전에 Decision Log 의무([CLAUDE.md:88](/D:/UNITY/UNITY_PROJECT/ActionFitPro/AF_CrowdCity/CLAUDE.md:88))와 함께 “bulk agent는 CrowdRoot 소유 pure data/render record, prefab 규약은 CrowdRoot와 소수 leader proxy에 적용”으로 명시적 피벗이 필요합니다.
- `DESIGN.md`, `INTERFACES.md`, `PREFAB_CONSTRUCTION_PLAN.md`의 Human clone·CC 권위·teardown 계약도 함께 갱신해야 합니다. 사용자 승인 전에는 구현을 시작할 수 없습니다.

## 6. 최종 권고

1. **DOTS가 아니라 커스텀 NativeArray SoA + Burst + `IJobParallelFor`**를 선택합니다. raw `unsafe`는 프로파일된 hotspot에만 후속 적용합니다.
2. **게임 전체 전면 재설계가 아니라 Crowd 서브시스템의 simulation+presentation 집중 재설계**입니다. GameSession/Input/Camera/HUD 및 외부 이벤트 계약은 유지합니다.
3. 모바일 만 단위는 **조건부 현실적**입니다. 1만은 합리적인 목표이고 5만은 stretch tier입니다. 특히 “5만 동시 시뮬레이션”과 “5만 전부 화면에 고품질 애니메이션 렌더”는 다른 목표이며, 후자는 aggressive LOD/culling/impostor 없이는 확인할 수 없습니다.

## 합의 후보

- 현 per-agent Human prefab 모델의 정확한 붕괴점은 확인 불가지만, 1만 이전 구조 교체가 필수다.
- 최소 변경안은 DOTS 전환이 아니라 기존 SoA를 NativeArray Jobs/Burst로 이식하는 것이다.
- 시뮬 선택과 무관하게 bulk Animator·SkinnedMeshRenderer·bone Transform을 제거하고 GPU 배치 렌더로 바꿔야 한다.
- bit-identical 결정성은 canonical order와 독립 RNG 스트림을 강제하면 동일 빌드/플랫폼에서 유지 가능하지만, 기존 경로·cross-ISA 동일성은 재보장 대상이다.
- 범위는 Crowd simulation+presentation 재설계이며 게임 전체 ECS 전환은 불필요하다.
- 10k는 현실적 목표, 50k는 실기기 scale ladder를 통과해야 하는 stretch 목표다.
