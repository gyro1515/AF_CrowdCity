역할: AF_CrowdCity Unity 프로젝트의 crowd 시뮬레이션을 "몇 십만(100k~500k) 개체" 규모까지 끌어올릴 수 있는지 코드 근거로 평가하는 독립 검증자. (앞선 라운드1에서 너는 800~2000명 전제로 "솔버 Burst화는 병목 아님(C)"이라 평가했는데, 사용자가 실제 목표는 몇 십만이라고 정정함. 전제가 바뀌었으니 재평가하라.)

전제(재평가 기준):
- 목표 동시 개체수 = 100,000 ~ 500,000 (모두 recruit/combat 대상인 gameplay agent라고 가정. 실제로 시각 crowd/LOD 분리 여지가 있으면 명시).
- 현재 아키텍처: agent 1명당 Human prefab clone(GameObject) + Transform + baked CharacterController + 개별 MeshRenderer(SkinnedMesh?). CrowdRoot가 SimTick에서 per-agent로 Transform.position을 읽고/쓴다. SoA는 AgentBuffer(managed 배열). SpatialGrid/CombatResolver/RecruitResolver는 managed class + List. WallSolver+SDF(NativeArray)만 Burst-shaped. neutral 이동에 Physics.Raycast, spawn에 Physics.CheckSphere 잔존. 단일 System.Random.

평가 질문(각각 코드 파일:라인 근거 인용, 추측 금지, 확인불가는 명시):
1. 현재 아키텍처 상한: agent당 GameObject+Transform+CharacterController+개별 렌더러 모델이 몇 십만에서 성립하는가? 구체적으로 어디서 먼저 무너지는가(Transform 계층/컬링 비용, GameObject/CC 메모리, 개별 렌더러 draw call/batching, GC, Instantiate 시간, SkinnedMeshRenderer 스키닝 비용)? 대략적 실효 상한 개체수는?
2. 렌더링 경로: 몇 십만을 그리려면 개별 MeshRenderer가 아니라 GPU instancing(BatchRendererGroup/Graphics.RenderMeshIndirect/DrawMeshInstancedIndirect) + 애니메이션 인스턴싱(GPU skinning/vertex-baked animation texture)이 필요한가? 이게 시뮬레이션과 별개의 독립 병목인가? 현재 렌더 경로는 무엇인가?
3. 시뮬레이션 경로: 단순 IJobParallelFor+Burst로 충분한가, 아니면 ECS/DOTS 엔티티 전환 또는 GPU compute(steering/SDF/grid를 compute shader로)가 필요한가? 현재 커널의 알고리즘 복잡도 한계(SpatialGrid 셀 크기/쿼리, CombatResolver/RecruitResolver의 per-pair 비용)를 몇 십만 규모로 외삽하면?
4. 결정성/게임플레이: 이 규모에서 기존 오라클(bit-identical) 결정성 계약을 유지하는 것이 현실적인가? combat/recruit 규칙(전순서 tie-break 등)이 몇 십만에서 O(?) 폭발하지 않는가? 결정성을 포기/완화해야 하면 그 근거와 대안.
5. 현실적 로드맵: 현재(2000) → 몇 십만으로 가는 단계별 마일스톤과 각 단계에서 새로 등장하는 병목. 각 단계가 CLAUDE.md의 MVP/Growth/Advanced 및 프리팹/소유권 규약과 어떻게 충돌/정합하는지 간단히.
6. 최종 권고: 몇 십만 목표에서 (A)현 아키텍처에 Burst+Job 증분으로 도달 가능 / (B)시뮬레이션은 native SoA+Job+GPU instancing 렌더로 부분 재설계 필요 / (C)ECS/DOTS 또는 GPU-sim으로 전면 재설계 필요 중 택1 + 1~2줄 근거.

조사: rg로 렌더 경로(Human prefab, MeshRenderer/SkinnedMeshRenderer, 애니메이터), CrowdRoot tick, 커널, GameConfig(현재 규모), GameResources를 확인. 렌더 관련 코드/프리팹 구성을 반드시 확인하라.

출력(간결): 질문 1~6 결론 + 핵심 코드 근거(파일:라인). 마지막 "합의 후보" 섹션에 다른 검증자와 합의 가능한 핵심 주장 4~6개.
