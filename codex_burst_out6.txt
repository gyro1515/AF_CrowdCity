## 2. Target end-state (sim 커널 구조)

### 소유권과 lifetime

`CrowdRoot`를 계속 feature owner로 둔다. 그 내부에 순수 C# `CrowdSimState : IDisposable`을 두고 모든 Native 컨테이너를 소유시킨다.

- `Initialize`에서 실제 population과 고정 map/team capacity에 맞춰 `Allocator.Persistent`로 한 번 할당한다.
- tick 중 resize, `NativeList` 증설, `Allocator.Temp/TempJob` 생성을 금지한다.
- `_simFence`로 마지막 `JobHandle`을 추적한다.
- `Shutdown`은 먼저 `_simFence.Complete()`한 뒤 Dispose한다.
- 부분 초기화 실패, 정상 `Shutdown`, `OnDestroy` 안전망 모두 같은 idempotent Dispose 경로를 사용한다.
- `[DeallocateOnJobCompletion]`은 사용하지 않는다.
- Transform이 아니라 Native 위치가 sim의 권위 상태다. `CrowdModel`의 follower 목록은 외부 표시/API 호환용 cache로만 유지한다.

### deterministic full grid

셀 저장 자체는 cap하지 않는다. 모든 agent를 보존하는 dense cell/lane range를 구성한다.

- `CellOfAgent[N]`
- `CountByCellLane[cellCount × laneCount]`
- `OffsetByCellLane[cellCount × laneCount + 1]`
- `AgentsByCellLane[N]`
- lane `0 = neutral`, `1 + TeamId = 해당 team`
- cell 내부 agent는 stable AgentId canonical order

최소 구현은 다음과 같다.

1. `IJobParallelFor`: agent별 cell/lane key 계산.
2. 단일 Burst `IJob`: canonical AgentId 순 count → prefix → scatter.
3. 전향 commit 뒤 위치를 다시 계산하지 않고 team lane만 O(N) re-lane한다.

Atomic count는 최종 정수에는 영향을 주지 않지만 구현 복잡도를 늘린다. 우선 serial Burst finalize를 사용하고, 이것이 실측 병목일 때만 고정 logical block histogram과 block-index 순 merge로 병렬화한다.

### tick pipeline

```text
pending state 소비 / team AI
        ↓
leader next-position 계산
        ↓
follower separation+steering / neutral wander+movement (parallel)
        ↓
position buffer swap
        ↓
post-move cell key 계산 (parallel)
        ↓
canonical grid finalize (serial Burst)
        ↓
recruit query / combat contact discovery (parallel)
        ↓
canonical recruit/combat/leader resolve (serial Burst)
        ↓
team 변경 commit → grid re-lane
        ↓
CrowdModel/Human sync → fact event publish
```

`IJobParallelFor` 대상:

- follower separation 및 steering
- neutral wander/movement
- SDF movement resolve
- agent별 grid cell/lane key 계산
- neutral별 recruit 후보 계산
- non-neutral별 combat directed-contact 계산
- agent별 fixed output/telemetry 기록

직렬로 남길 단계:

- pending 상태 소비
- 현재 최대 4개 team의 heading/rival AI 결정과 leader 이동
- grid prefix/canonical scatter
- team-pair contact reduction과 accumulator
- victim 선택 순서와 leader elimination
- conversion/elimination commit
- managed Transform/Animator/material 동기화
- 이벤트 발행

논리적으로 직렬인 계산은 main thread가 아니라 단일 Burst `IJob`으로 실행해도 된다. 중요한 계약은 실행 순서가 하나로 고정된다는 점이다.

SDF ON 상태로 M-sim-2를 수행하려면 M-sim-2에서 이미 `WallFieldView`가 필요하다. `WallField` owner와 다음 blittable read-only view를 분리한다.

- `[ReadOnly] NativeArray<float> Samples`
- origin, cell size, dimensions, bias/clearance 메타
- Burst-callable `Phi`, `Gradient`, `Resolve`

Physics 제거 자체는 M-sim-3이지만, live SDF movement의 job 호환화는 M-sim-2 범위다.

## 3. 순서화된 마일스톤 (각각: 변경 스코프 + 검증 게이트)

### M-sim-0 헤드리스 배치 2000/5000+ 단계별 프로파일(병목 sub-stage 실측 — grid/recruit/combat/steering 중 무엇인지 확정)

변경 스코프:

- 현재 profile harness의 `100/300/500/800` 하드코딩을 CLI 인자로 바꾼다.
  - `-profileScales`
  - `-profileSeeds`
  - `-profileWarmupTicks`
  - `-profileTimingTicks`
  - `-profileGcTicks`
- 최소 full-root scale을 `2000,5000`으로 한다. 10K 이상은 메모리 허용 범위에서 추가한다.
- 현재 harness의 `agents`가 neutral을 제외하는 문제를 고쳐 실제 `OracleAgentCount`를 기록한다.
- 기존 시간 marker에 다음 work counter를 추가한다.
  - grid build entries
  - separation/recruit/combat candidate visits
  - exact-radius qualifying count
  - touching pair 및 unique pair 수
  - victim count, comparison/sort work
  - cap은 아직 OFF
- 반드시 실제 CrowdRoot prefab을 instantiate하거나 명시적으로 live SDF ON을 설정한다.
  - `_useSdfSolver == true`
  - SDF load 성공
  - `CC.Move` fallback 호출 0
- 현재 harness는 빈 GameObject에 `AddComponent<CrowdRoot>()`를 사용하므로 live prefab의 SDF ON을 우회할 가능성이 코드상 확인됐다. 이 문제를 먼저 고치지 않은 profile은 기준선으로 쓰지 않는다.

검증 게이트:

- 같은 머신·Unity/Burst 설정과 동일 seed/tick으로 독립 프로세스 3회 이상 실행한다.
- A/A 반복으로 측정 노이즈 밴드를 먼저 만든다.
- `Total`, grid, recruit, combat, steering의 median/p95와 work counter 증가가 같은 sub-stage를 일관되게 지목해야 한다.
- sub-stage 순위가 실행마다 뒤집히면 marker를 더 세분화하고 M-sim-1로 넘어가지 않는다.
- direct `SimTick` 결과와 Development Player의 `GameplayRoot.Update → CrowdRoot.SimTick`에서 주범이 일치해야 한다.
- 이 단계의 성능 수치는 모두 실측 전이므로 현재는 외삽할 수 없다. 목표 디바이스의 frame budget과 A/A 노이즈를 본 뒤 최종 상대 개선률/절대 ms gate를 고정한다.

### M-sim-1 grid 쿼리 밀도 캡핑(초선형 항 제거) — 알고리즘 설계 포함

변경 스코프:

- `SpatialGrid`를 모든 agent를 보존하는 `BoundedLaneGrid` 책임으로 변경한다.
- 저장량은 자르지 않고 recruit/combat/separation query의 방문량만 제한한다.
- recruit/combat에는 team별 독립 budget을 적용한다.
- separation에는 own-team budget을 적용한다.
- 현재 최대 leader 4명의 exact query와 최대 rival 3명의 0.4초 주기 AI query는 cap하지 않는다. 둘 다 전체적으로 O(N)이므로 의미 변경 없이 유지한다.
- victim insertion sort를 제거한다.
  - rate-limit 경로: emit budget이 작으면 bounded max-heap으로 필요한 prefix만 선택
  - emit budget이 크면 deterministic fixed-pass radix
  - instant 경로: 전 victim deterministic radix
- cap 파라미터는 `GameConfigSO` source → immutable `SimTuning` snapshot으로 전달한다. 값은 M-sim-0의 occupancy/candidate histogram 전에는 확정하지 않는다.

검증 게이트:

- 각 query의 방문량이 계약식 이하임을 counter로 정확히 증명한다.
- dense fixture에서 `work/N`이 density와 함께 증가하지 않아야 한다.
- `budgetHit == false`인 fixture에서는 legacy 규칙과 동일해야 한다.
- cap-hit fixture는 legacy byte equality를 요구하지 않는다. recruit 지연, claimant mismatch, contact strength deficit, conversion/elimination 변화, separation 방향 편차를 A/B하여 승인받은 뒤에만 오라클을 갱신한다.
- 대상 resolver 시간의 paired 개선이 A/A 노이즈 밴드 밖이어야 하고 전체 SimTick이 악화되지 않아야 한다.
- Burst/멀티스레드는 아직 적용하지 않는다. 이 단계의 성공 조건은 상수배 개선이 아니라 초선형 work term 제거다.

### M-sim-2 NativeArray SoA + Burst + IJobParallelFor 이식·병렬화

변경 스코프를 세 sub-step으로 나눈다.

1. M2-a — Native storage, serial:
   - managed `AgentBuffer`와 흩어진 배열을 `NativeAgentSoA/CrowdSimState`로 이전
   - 여전히 serial 실행
   - Transform mirror를 제거하고 Native position을 authority로 전환

2. M2-b — Burst canonical serial:
   - `Vector2/Mathf` hot path를 `float2/math`로 통일
   - `WallFieldView`와 Burst-callable SDF solver 도입
   - 공유 `System.Random`을 per-agent/per-team stream으로 교체
   - canonical grid/recruit/combat reduction 확정
   - 이 단계는 RNG sequence와 float 연산이 달라질 수 있으므로 behavior A/B 승인 후 새 기준선을 만든다.

3. M2-c — parallel:
   - follower/neutral movement, grid key, recruit query, combat discovery를 `IJobParallelFor`로 전환
   - job은 자기 agent의 fixed output slot과 자기 RNG state만 쓴다.
   - shared append, float atomic reduction, worker-local merge 순서 의존을 금지한다.

검증 게이트:

- M2-a는 가능한 범위에서 M-sim-1 oracle과 byte 비교한다. 첫 divergence가 나오면 storage 이전 외 연산 순서가 바뀌지 않았는지 조사한다.
- M2-b는 RNG/math 전환이 있으므로 M1 byte equality를 자동 전제하지 않는다. A/B 승인 후 `M2-canonical` baseline을 생성한다.
- M2-c의 모든 worker/batch permutation은 `M2-canonical`과 byte-identical이어야 한다.
- schedule+complete를 포함한 전체 SimTick으로 측정한다.
- 작은 N의 job overhead와 2000/5000의 개선을 모두 보고한다.
- Persistent container lifecycle test, leak 0, SimTick managed allocation 0을 통과해야 한다.

### M-sim-3 잔존 Physics.Raycast→SDF 질의 대체 + baked CC 제거

변경 스코프:

- neutral wander Raycast를 고정-step SDF segment-clearance query로 교체한다.
- 현재 checkout에 추가로 존재하는 `RivalAiDriver.ProbeClearance`의 정면/좌/우 Raycast도 같은 SDF query로 교체한다.
- 샘플 간격은 최대 `0.5 × SDF cell size`, 후보 방향 순서와 refinement 횟수를 고정한다.
- SDF 누락 시 CC로 조용히 fallback하지 않는다. 초기화 실패 또는 명시적 feature disable로 처리한다.
- baked `CharacterController`와 다음 책임을 제거한다.
  - controller 배열/취득
  - `CC.Move` fallback
  - Unit-layer self-collision 보정
  - profile의 CCMove 구간
  - setup/validator의 “CC 필수” 계약
- Human prefab과 scene setup을 “CC 없음”으로 수렴시킨다.
- spawn `Physics.CheckSphere`는 초기화 1회이며 SimTick 병목이 아니므로 최소 변경안에서는 유지한다. 완전 Physics-zero가 별도 요구가 되면 SDF spawn-clearance로 후속 교체한다.

검증 게이트:

- SDF bake source가 기존 Raycast/CC가 보던 정적 collider를 모두 포함하는지 validator로 확인한다.
- neutral/rival probe A/B:
  - 후보 accept/reject
  - chosen heading
  - first-obstacle 거리
- 이동 A/B:
  - 벽 침투 깊이와 tunneling 횟수
  - clearance
  - 실제 변위와 slide angle
  - stuck/oscillation 지속 tick
  - endpoint/RMS 경로 편차
- setup 재실행 후에도 prefab/runtime clone의 CC가 0이어야 한다.
- runtime Raycast가 0이어야 한다. 유지한 spawn CheckSphere는 명시적 init-only 예외다.
- SDF 전환 역시 결과가 바뀔 수 있으므로 behavior 승인 후 M3 baseline을 별도로 재기준화한다.
- 최종 Development Player에서 `GameplayRoot.Update`, SimTick, fixed-step catch-up, frame p95/p99를 재측정한다.

## 4. 결정성 계획

### FloatMode/FloatPrecision

모든 sim job과 Burst-callable 핵심 메서드에 명시한다.

```csharp
[BurstCompile(
    FloatMode = FloatMode.Strict,
    FloatPrecision = FloatPrecision.Standard)]
```

- `Fast`는 사용하지 않는다.
- cross-ISA 계약이 없으므로 `FloatMode.Deterministic`을 필수화하지 않는다.
- build manifest에 Unity/Burst/Collections/Mathematics 버전과 float 설정을 기록한다.
- float sum/reduction은 stable AgentId/team-pair 순 직렬 reduction으로 수행한다.
- atomic float나 worker completion 순서 기반 reduction을 금지한다.

### RNG per-agent stream

공유 `System.Random`은 job에 전달하지 않는다.

- 명시적 정수 RNG 알고리즘을 `DeterministicRng`에 고정한다. 권고는 `uint4` 상태의 xoshiro 계열과 고정 bit-to-float 변환이다.
- 초기화는 `(globalSeed, stableAgentId 또는 teamId, streamTag)`를 정수 mix한다.
- 0 상태는 고정 non-zero seed로 치환한다.
- stream 구분:
  - spawn rejection: 직렬 `SpawnRng`
  - neutral wander: agent별 `AgentRngState`
  - rival/team AI tie-break: team별 `TeamRngState`
- random float는 고정 상위 24bit를 `2^-24`로 변환한다.
- job은 자기 index의 RNG state만 갱신한다.
- cap의 rotating cursor는 RNG draw를 소비하지 않고 `(queryAgentId, cellIndex, lane, simTick)` pure hash로 계산한다.

현재 checkout에는 `CrowdRoot` RNG 외에 rival별 `RivalAiDriver` RNG가 확인됐다. 제공된 “단일 System.Random” 설명과 불일치하므로 rebase 후 전수 재확인하되, target end-state는 양쪽 모두 위 stream 계약으로 흡수한다.

### canonical order

- Agent 기준: stable AgentId.
- Grid build: cell key → lane → AgentId.
- Query tie: distanceSq → AgentId.
- Recruit commit: neutral AgentId 순.
- Combat edge: `(minAgentId, maxAgentId)`로 canonicalize → sort → unique.
- Team-pair reduction: `(winnerTeamId, loserTeamId)` 순.
- Victim: `(assignedDistanceSq, victimAgentId)` 순.
- Leader resolve: leader/team ID 순.
- Conversion, elimination, `CrowdModel` sync, event publish도 같은 canonical commit 순서를 사용한다.

`NativeParallelMultiHashMap`의 enumeration이나 parallel writer append 순서는 gameplay 규칙에 사용하지 않는다.

### 오라클 재기준선

1. 리팩토링 rebase 직후 serial 구현을 same-seed 2회 실행해 byte-identical baseline을 만든다.
2. M-sim-0은 동작 변경이 없으므로 baseline 유지가 필수다.
3. M-sim-1:
   - cap 미발동 fixture는 이전 기준선 유지
   - cap 발동 fixture는 A/B 승인 후 manifest와 함께 한 번만 갱신
4. M2-a는 M1과 비교한다.
5. M2-b의 RNG/math 전환은 승인 후 `M2-canonical`을 만든다.
6. M2-c parallel은 모든 permutation에서 `M2-canonical`과 byte-identical이어야 한다.
7. M3 SDF 의미 변경도 A/B 승인 후 별도 재기준화한다.
8. 새 baseline 자체를 다시 same-seed 2회 byte 비교한다.

snapshot은 AgentId 순으로 다음을 포함한다.

- position raw float bits
- team, leader flag
- velocity/heading/wander timer
- agent/team RNG state
- combat accumulator
- elimination 상태
- canonical event transcript

baseline manifest에는 commit, platform, package versions, SDF hash, cap 값, seed/count/ticks를 기록한다. 테스트와 baseline을 같은 변경에서 자동 덮어쓰는 방식은 금지한다.

### worker/batch permutation

같은 초기 snapshot을 다음 조합으로 매번 새로 구성한다.

- worker: `0`, `1`, default/max available
- batch: `1`, `16`, `64`, `127`, `> agentCount`
- 동일 조합 반복 및 실행 순서 변경

각 tick `Complete()` 후 canonical snapshot을 byte 비교한다. `JobsUtility.JobWorkerCount`는 `try/finally`에서 원복하거나 `ResetJobWorkerCount()`를 호출한다.

## 5. 밀도 캡핑 알고리즘 설계

### 선택안: full storage + bounded lane query

셀당 agent 저장 상한은 두지 않는다. 저장을 잘라내면 exact leader/AI와 oracle이 깨지고 특정 agent가 영구 누락된다.

각 bounded query는 다음 순서로 실행한다.

1. broad radius에 해당하는 cell offset stencil을 초기화 때 생성한다.
2. 실제 query 위치에서 cell AABB 최소거리와 cell key로 canonical cell 순서를 정한다.
3. 필요한 team/neutral lane만 선택한다.
4. lane마다 독립적인 candidate visit budget `B`를 적용한다.
5. 한 dense cell이 예산을 독점하지 않도록 active cell ranges를 round-robin한다.
6. cell range 시작점은 query ID/cell/lane/tick hash로 회전시켜 영구 기아를 줄인다.
7. candidate는 self/team/radius filter 이전에 budget을 소비한다. 그래야 strict bound가 유지된다.
8. 실제 pair radius를 통과한 후보만 fixed max-heap에 `(distanceSq, AgentId)`로 유지한다.
9. 결과는 canonical key로 정렬해 반환한다.

복잡도는 고정 team 수와 radius stencil에서 query당 `O(B log K)`, 전체 `O(N·B)`다. Grid build는 O(N + cell×lane)다.

### query별 정책

| Query | Budget/keep | 보존 전략 |
|---|---|---|
| Recruit | team별 `BRecruitPerTeam`, team별 `K=1` | 각 team의 nearest를 구한 뒤 전체 `(distanceSq, claimantId)` 최소 선택 |
| Combat | enemy team별 `BCombatPerEnemyTeam`, `K=min(B, PairNormalizer)` | team이 다른 team을 가리지 않게 quota 분리; fixed edge slot 후 sort/unique |
| Separation | own-team `BSeparation`, 초기 `K=B` | 별도 top-K truncation 없이 budget만 의미 변경 원인으로 제한 |
| Leader | cap 없음 | 현재 최대 4명이라 exact scan도 O(N); escort/killer 의미 보존 |
| Rival AI | cap 없음 | 현재 최대 3명, 0.4초 주기라 amortized O(N); neutral 방향 합 exact 유지 |

현재 asset의 `PairNormalizer=15`는 combat strength가 그 지점에서 포화하는 기존 규칙에서 나온 값이다. rebase 후 재확인한다. 다른 B/K 값은 M-sim-0 전에는 근거가 없어 미확정이다.

### combat edge와 victim 처리

- 각 agent/enemy-team/K에 고정 contact slot을 둔다.
- 양쪽 query 중 한쪽만 pair를 발견해도 edge를 보존한다.
- `(minId,maxId)` sort/unique로 중복을 한 번만 센다.
- team-pair contact count는 기존 `PairNormalizer`에서 saturating add한다.
- victim winner는 기존처럼 strict-larger team 중 최근접, 거리 동률은 낮은 team ID다.
- rate-limited victim 선택:
  - `emitK = min(floor(accumulator[pair]), victimCount)`
  - 작은 K: bounded max-heap으로 정확한 top-K
  - 큰 K: deterministic fixed-pass radix
- instant mode는 모든 victim을 radix로 정렬한다.
- 출력 순서는 기존 pair 순서와 `(distanceSq, AgentId)`를 유지한다.

### gameplay 의미 훼손 최소화

보장되는 것:

- query 반경 자체를 줄이지 않는다.
- 선택된 후보에는 기존 exact pair radius를 그대로 적용한다.
- false positive recruit/combat은 만들지 않는다.
- team별 quota로 한 team의 밀도가 다른 team을 가리지 않게 한다.
- 모든 neutral/non-neutral을 매 tick query한다.
- 회전 cursor로 같은 overflow agent가 영구 배제되는 문제를 줄인다.
- cap 미발동 시 기존 규칙과 같은 결과를 요구한다.

보장할 수 없는 것:

- 임의 개수 agent가 같은 위치/lane에 겹칠 수 있는 모델에서 finite B와 “모든 실제 접촉을 같은 tick에 정확히 판정”은 동시에 만족할 수 없다.
- cap-hit 시 nearest claimant/contact가 누락되어 recruitment/conversion이 지연되거나 separation 방향이 달라질 수 있다.

따라서 cap은 명시적인 bounded approximation이다. 모든 접촉의 즉시 exact 보존이 절대 조건이라면 cap을 포기하고 gameplay occupancy 상한을 강제하거나 별도 exact aggregate/hierarchy 설계로 범위를 변경해야 한다.

### cap 파라미터

M-sim-0 이후 확정할 항목:

- `RecruitCandidateBudgetPerTeam`
- `CombatCandidateBudgetPerEnemyTeam`
- `SeparationCandidateBudget`
- `SeparationKeepCount` — 최초에는 budget과 같게 설정
- cap-hit 허용률
- shadow uncapped query sampling 빈도

`BCombat >= KCombat`, 모든 budget 양수, team 상한을 `OnValidate`/scene validator에서 검증한다.

## 6. 검증 방법론

### 하네스 확장

- full-root profile: 2000/5000 및 가능한 10K
- M2 이후 presentation-free kernel harness: 10K/20K 이상
- 실제 CrowdRoot prefab/SDF ON 경로
- 실제 전체 agent 수 기록
- 동일 seed/count/ticks와 고정 `dt=0.02`
- 독립 프로세스 최소 3회
- A/B는 `A-B-B-A` 순서로 실행
- median, p95, paired ratio와 95% CI 기록
- CPU, Unity/Burst 버전, worker 수, build hash 기록

현재 성능 수치는 없으므로 모든 예상 이득은 외삽이다. “대폭 감소”의 최종 수치는 M-sim-0 A/A noise와 목표 디바이스 SimTick budget을 근거로 승인한 뒤 고정한다.

### 알고리즘 gate

- `CandidatesVisited <= QueryCount × LaneCount × B`
- 2000/5000+에서 candidate work/N이 density 증가에 따라 증가하지 않음
- victim 경로에서 v² comparison 제거
- cap-off/cap-unhit fixture는 reference와 동일
- cap-hit 여부와 skipped broad-phase entry 수 telemetry
- combat directed/unique/duplicate edge 및 pair saturation 기록

### 거동 A/B

Critical fixture는 100% 보존한다.

- recruit nearest/AgentId tie-break
- strict-larger team만 승리
- equal team no conversion
- pair accumulator/emit 순서
- leader escort immunity
- leader killer count/tie-break
- radius 밖 false contact 0
- instant/rate-limit 양 모드
- insertion/grid build permutation

Dense statistical A/B는 다음을 기록한다.

- 최초 접촉 대비 recruit 지연 tick
- claimant/team mismatch
- combat pre-saturation contact deficit
- tick별 conversion 수
- victim/leader elimination team 및 tick
- team-count time series와 최종 winner
- separation angle/magnitude delta
- position/velocity의 p50/p95/max 편차

허용 임계치는 M-sim-0 결과와 실제 gameplay 영상 비교 후 승인한다. 근거 없는 수치를 지금 고정하지 않는다.

### 결정성/oracle

- 모든 scale/seed 조합을 same-seed 2회 비교한다. 현재처럼 첫 조합만 비교하지 않는다.
- 최초 divergence tick과 필드 diff를 출력한다.
- worker/batch permutation 전체를 비교한다.
- event transcript와 RNG/internal state도 byte oracle에 포함한다.

### GC/무할당/lifetime

- warmup 뒤 지원되는 Unity API에서 `GC.GetAllocatedBytesForCurrentThread()`로 1000 ticks delta 0을 요구한다.
- Development Player에서는 `ProfilerRecorder` GC allocation counter로 300 frame 이상 연속 0을 교차 확인한다.
- 현재 `GC.GetTotalMemory(false)` delta는 참고치로만 유지한다.
- `Initialize → ticks → Shutdown` 반복 테스트:
  - 모든 handle Complete
  - 모든 Native 컨테이너 `IsCreated == false`
  - 중복 Shutdown 안전
  - Native leak detection 로그 0
- `GC.GetAllocatedBytesForCurrentThread()`의 현 Unity compatibility는 컴파일 gate에서 확인한다.

### 최종 성능 gate

- 각 단계 개선의 paired 95% CI가 A/A 노이즈 밴드 밖의 개선 방향이어야 한다.
- 관련 없는 sub-stage는 A/A 등가 밴드 안이어야 한다.
- M-sim-1은 알고리즘 work bound가 hard gate다.
- M-sim-2는 schedule/complete 포함 전체 SimTick 개선이 hard gate다.
- 최종 Player는 목표 디바이스에서 승인된 SimTick/frame budget을 만족해야 한다.
- 절대 ms/fps나 개선 퍼센트는 현재 미실측이므로 확정하지 않는다.

## 2. Target end-state (sim 커널 구조)

### 소유권과 lifetime

`CrowdRoot`를 계속 feature owner로 둔다. 그 내부에 순수 C# `CrowdSimState : IDisposable`을 두고 모든 Native 컨테이너를 소유시킨다.

- `Initialize`에서 실제 population과 고정 map/team capacity에 맞춰 `Allocator.Persistent`로 한 번 할당한다.
- tick 중 resize, `NativeList` 증설, `Allocator.Temp/TempJob` 생성을 금지한다.
- `_simFence`로 마지막 `JobHandle`을 추적한다.
- `Shutdown`은 먼저 `_simFence.Complete()`한 뒤 Dispose한다.
- 부분 초기화 실패, 정상 `Shutdown`, `OnDestroy` 안전망 모두 같은 idempotent Dispose 경로를 사용한다.
- `[DeallocateOnJobCompletion]`은 사용하지 않는다.
- Transform이 아니라 Native 위치가 sim의 권위 상태다. `CrowdModel`의 follower 목록은 외부 표시/API 호환용 cache로만 유지한다.

### NativeArray SoA

| 데이터 | 컨테이너 | 내용 |
|---|---|---|
| 불변 agent identity | `NativeArray<int>`, `NativeArray<float>`, `NativeArray<byte>` | `AgentId`, `Scale`, `IsLeader` |
| mutable agent state | `NativeArray<int>` | `Team` |
| 위치 double buffer | `NativeArray<float2>` 2개 | `PositionCurrent`, `PositionNext`; tick 후 swap하여 이전/현재 위치를 동시에 보존 |
| 이동 상태 | `NativeArray<float2>` | `Velocity` |
| neutral 상태 | `NativeArray<float>` | `WanderHeading`, `WanderTimer` |
| agent RNG | `NativeArray<uint4>` | agent별 wander RNG state |
| team 상태 | team 크기의 NativeArray | `LeaderAgentIndex`, `TeamHeading`, `LeaderYaw`, `MemberCount`, `PublishedMemberCount`, `Eliminated`, team AI RNG |
| combat 상태 | team-pair 크기의 NativeArray | 기존 수치 형식을 유지한 ordered-pair accumulator와 포화 contact count |
| canonical order | `NativeArray<int>` | `AgentIndexByIdOrder` |
| recruit 결과 | agent 크기의 고정 배열 | claimant index/team/distance/valid |
| combat 결과 | agent×enemy-team×K 고정 슬롯 | contact target/distance/valid; atomic append 금지 |
| victim scratch | agent 크기의 고정 배열 | pair, distance, AgentId, agent index |
| telemetry | agent별 고정 슬롯 | visit count, cap hit, returned count 등 |

현재 population은 spawn 후 고정이고 실제 제거가 없으므로, rebase 결과에서도 제거 개념이 없다면 speculative `Alive` 배열을 추가하지 않는다.

### deterministic full grid

셀 저장 자체는 cap하지 않는다. 모든 agent를 보존하는 dense cell/lane range를 구성한다.

- `CellOfAgent[N]`
- `CountByCellLane[cellCount × laneCount]`
- `OffsetByCellLane[cellCount × laneCount + 1]`
- `AgentsByCellLane[N]`
- lane `0 = neutral`, `1 + TeamId = 해당 team`
- cell 내부 agent는 stable AgentId canonical order

최소 구현은 다음과 같다.

1. `IJobParallelFor`: agent별 cell/lane key 계산.
2. 단일 Burst `IJob`: canonical AgentId 순 count → prefix → scatter.
3. 전향 commit 뒤 위치를 다시 계산하지 않고 team lane만 O(N) re-lane한다.

Atomic count는 최종 정수에는 영향을 주지 않지만 구현 복잡도를 늘린다. 우선 serial Burst finalize를 사용하고, 이것이 실측 병목일 때만 고정 logical block histogram과 block-index 순 merge로 병렬화한다.

### tick pipeline

```text
pending state 소비 / team AI
        ↓
leader next-position 계산
        ↓
follower separation+steering / neutral wander+movement (parallel)
        ↓
position buffer swap
        ↓
post-move cell key 계산 (parallel)
        ↓
canonical grid finalize (serial Burst)
        ↓
recruit query / combat contact discovery (parallel)
        ↓
canonical recruit/combat/leader resolve (serial Burst)
        ↓
team 변경 commit → grid re-lane
        ↓
CrowdModel/Human sync → fact event publish
```

`IJobParallelFor` 대상:

- follower separation 및 steering
- neutral wander/movement
- SDF movement resolve
- agent별 grid cell/lane key 계산
- neutral별 recruit 후보 계산
- non-neutral별 combat directed-contact 계산
- agent별 fixed output/telemetry 기록

직렬로 남길 단계:

- pending 상태 소비
- 현재 최대 4개 team의 heading/rival AI 결정과 leader 이동
- grid prefix/canonical scatter
- team-pair contact reduction과 accumulator
- victim 선택 순서와 leader elimination
- conversion/elimination commit
- managed Transform/Animator/material 동기화
- 이벤트 발행

논리적으로 직렬인 계산은 main thread가 아니라 단일 Burst `IJob`으로 실행해도 된다. 중요한 계약은 실행 순서가 하나로 고정된다는 점이다.

SDF ON 상태로 M-sim-2를 수행하려면 M-sim-2에서 이미 `WallFieldView`가 필요하다. `WallField` owner와 다음 blittable read-only view를 분리한다.

- `[ReadOnly] NativeArray<float> Samples`
- origin, cell size, dimensions, bias/clearance 메타
- Burst-callable `Phi`, `Gradient`, `Resolve`

Physics 제거 자체는 M-sim-3이지만, live SDF movement의 job 호환화는 M-sim-2 범위다.

  - emit budget이 크면 deterministic fixed-pass radix
  - instant 경로: 전 victim deterministic radix
- cap 파라미터는 `GameConfigSO` source → immutable `SimTuning` snapshot으로 전달한다. 값은 M-sim-0의 occupancy/candidate histogram 전에는 확정하지 않는다.

검증 게이트:

- 각 query의 방문량이 계약식 이하임을 counter로 정확히 증명한다.
- dense fixture에서 `work/N`이 density와 함께 증가하지 않아야 한다.
- `budgetHit == false`인 fixture에서는 legacy 규칙과 동일해야 한다.
- cap-hit fixture는 legacy byte equality를 요구하지 않는다. recruit 지연, claimant mismatch, contact strength deficit, conversion/elimination 변화, separation 방향 편차를 A/B하여 승인받은 뒤에만 오라클을 갱신한다.
- 대상 resolver 시간의 paired 개선이 A/A 노이즈 밴드 밖이어야 하고 전체 SimTick이 악화되지 않아야 한다.
- Burst/멀티스레드는 아직 적용하지 않는다. 이 단계의 성공 조건은 상수배 개선이 아니라 초선형 work term 제거다.

### M-sim-2 NativeArray SoA + Burst + IJobParallelFor 이식·병렬화

변경 스코프를 세 sub-step으로 나눈다.

1. M2-a — Native storage, serial:
   - managed `AgentBuffer`와 흩어진 배열을 `NativeAgentSoA/CrowdSimState`로 이전
   - 여전히 serial 실행
   - Transform mirror를 제거하고 Native position을 authority로 전환

2. M2-b — Burst canonical serial:
   - `Vector2/Mathf` hot path를 `float2/math`로 통일
   - `WallFieldView`와 Burst-callable SDF solver 도입
   - 공유 `System.Random`을 per-agent/per-team stream으로 교체
   - canonical grid/recruit/combat reduction 확정
   - 이 단계는 RNG sequence와 float 연산이 달라질 수 있으므로 behavior A/B 승인 후 새 기준선을 만든다.

3. M2-c — parallel:
   - follower/neutral movement, grid key, recruit query, combat discovery를 `IJobParallelFor`로 전환
   - job은 자기 agent의 fixed output slot과 자기 RNG state만 쓴다.
   - shared append, float atomic reduction, worker-local merge 순서 의존을 금지한다.

검증 게이트:

- M2-a는 가능한 범위에서 M-sim-1 oracle과 byte 비교한다. 첫 divergence가 나오면 storage 이전 외 연산 순서가 바뀌지 않았는지 조사한다.
- M2-b는 RNG/math 전환이 있으므로 M1 byte equality를 자동 전제하지 않는다. A/B 승인 후 `M2-canonical` baseline을 생성한다.
- M2-c의 모든 worker/batch permutation은 `M2-canonical`과 byte-identical이어야 한다.
- schedule+complete를 포함한 전체 SimTick으로 측정한다.
- 작은 N의 job overhead와 2000/5000의 개선을 모두 보고한다.
- Persistent container lifecycle test, leak 0, SimTick managed allocation 0을 통과해야 한다.

### M-sim-3 잔존 Physics.Raycast→SDF 질의 대체 + baked CC 제거

변경 스코프:

- neutral wander Raycast를 고정-step SDF segment-clearance query로 교체한다.
- 현재 checkout에 추가로 존재하는 `RivalAiDriver.ProbeClearance`의 정면/좌/우 Raycast도 같은 SDF query로 교체한다.
- 샘플 간격은 최대 `0.5 × SDF cell size`, 후보 방향 순서와 refinement 횟수를 고정한다.
- SDF 누락 시 CC로 조용히 fallback하지 않는다. 초기화 실패 또는 명시적 feature disable로 처리한다.
- baked `CharacterController`와 다음 책임을 제거한다.
  - controller 배열/취득
  - `CC.Move` fallback
  - Unit-layer self-collision 보정
  - profile의 CCMove 구간
  - setup/validator의 “CC 필수” 계약
- Human prefab과 scene setup을 “CC 없음”으로 수렴시킨다.
- spawn `Physics.CheckSphere`는 초기화 1회이며 SimTick 병목이 아니므로 최소 변경안에서는 유지한다. 완전 Physics-zero가 별도 요구가 되면 SDF spawn-clearance로 후속 교체한다.

검증 게이트:

- SDF bake source가 기존 Raycast/CC가 보던 정적 collider를 모두 포함하는지 validator로 확인한다.
- neutral/rival probe A/B:
  - 후보 accept/reject
  - chosen heading
  - first-obstacle 거리
- 이동 A/B:
  - 벽 침투 깊이와 tunneling 횟수
  - clearance
  - 실제 변위와 slide angle
  - stuck/oscillation 지속 tick
  - endpoint/RMS 경로 편차
- setup 재실행 후에도 prefab/runtime clone의 CC가 0이어야 한다.
- runtime Raycast가 0이어야 한다. 유지한 spawn CheckSphere는 명시적 init-only 예외다.
- SDF 전환 역시 결과가 바뀔 수 있으므로 behavior 승인 후 M3 baseline을 별도로 재기준화한다.
- 최종 Development Player에서 `GameplayRoot.Update`, SimTick, fixed-step catch-up, frame p95/p99를 재측정한다.

## 4. 결정성 계획

### FloatMode/FloatPrecision

모든 sim job과 Burst-callable 핵심 메서드에 명시한다.

```csharp
[BurstCompile(
    FloatMode = FloatMode.Strict,
    FloatPrecision = FloatPrecision.Standard)]
```

- `Fast`는 사용하지 않는다.
- cross-ISA 계약이 없으므로 `FloatMode.Deterministic`을 필수화하지 않는다.
- build manifest에 Unity/Burst/Collections/Mathematics 버전과 float 설정을 기록한다.
- float sum/reduction은 stable AgentId/team-pair 순 직렬 reduction으로 수행한다.
- atomic float나 worker completion 순서 기반 reduction을 금지한다.

### RNG per-agent stream

공유 `System.Random`은 job에 전달하지 않는다.

- 명시적 정수 RNG 알고리즘을 `DeterministicRng`에 고정한다. 권고는 `uint4` 상태의 xoshiro 계열과 고정 bit-to-float 변환이다.
- 초기화는 `(globalSeed, stableAgentId 또는 teamId, streamTag)`를 정수 mix한다.
- 0 상태는 고정 non-zero seed로 치환한다.
- stream 구분:
  - spawn rejection: 직렬 `SpawnRng`
  - neutral wander: agent별 `AgentRngState`
  - rival/team AI tie-break: team별 `TeamRngState`
- random float는 고정 상위 24bit를 `2^-24`로 변환한다.
- job은 자기 index의 RNG state만 갱신한다.
- cap의 rotating cursor는 RNG draw를 소비하지 않고 `(queryAgentId, cellIndex, lane, simTick)` pure hash로 계산한다.

현재 checkout에는 `CrowdRoot` RNG 외에 rival별 `RivalAiDriver` RNG가 확인됐다. 제공된 “단일 System.Random” 설명과 불일치하므로 rebase 후 전수 재확인하되, target end-state는 양쪽 모두 위 stream 계약으로 흡수한다.

### canonical order

- Agent 기준: stable AgentId.
- Grid build: cell key → lane → AgentId.
- Query tie: distanceSq → AgentId.
- Recruit commit: neutral AgentId 순.
- Combat edge: `(minAgentId, maxAgentId)`로 canonicalize → sort → unique.
- Team-pair reduction: `(winnerTeamId, loserTeamId)` 순.
- Victim: `(assignedDistanceSq, victimAgentId)` 순.
- Leader resolve: leader/team ID 순.
- Conversion, elimination, `CrowdModel` sync, event publish도 같은 canonical commit 순서를 사용한다.

`NativeParallelMultiHashMap`의 enumeration이나 parallel writer append 순서는 gameplay 규칙에 사용하지 않는다.

### 오라클 재기준선

1. 리팩토링 rebase 직후 serial 구현을 same-seed 2회 실행해 byte-identical baseline을 만든다.
2. M-sim-0은 동작 변경이 없으므로 baseline 유지가 필수다.
3. M-sim-1:
   - cap 미발동 fixture는 이전 기준선 유지
   - cap 발동 fixture는 A/B 승인 후 manifest와 함께 한 번만 갱신
4. M2-a는 M1과 비교한다.
5. M2-b의 RNG/math 전환은 승인 후 `M2-canonical`을 만든다.
6. M2-c parallel은 모든 permutation에서 `M2-canonical`과 byte-identical이어야 한다.
7. M3 SDF 의미 변경도 A/B 승인 후 별도 재기준화한다.
8. 새 baseline 자체를 다시 same-seed 2회 byte 비교한다.

snapshot은 AgentId 순으로 다음을 포함한다.

- position raw float bits
- team, leader flag
- velocity/heading/wander timer
- agent/team RNG state
- combat accumulator
- elimination 상태
- canonical event transcript

baseline manifest에는 commit, platform, package versions, SDF hash, cap 값, seed/count/ticks를 기록한다. 테스트와 baseline을 같은 변경에서 자동 덮어쓰는 방식은 금지한다.

### worker/batch permutation

같은 초기 snapshot을 다음 조합으로 매번 새로 구성한다.

- worker: `0`, `1`, default/max available
- batch: `1`, `16`, `64`, `127`, `> agentCount`
- 동일 조합 반복 및 실행 순서 변경

각 tick `Complete()` 후 canonical snapshot을 byte 비교한다. `JobsUtility.JobWorkerCount`는 `try/finally`에서 원복하거나 `ResetJobWorkerCount()`를 호출한다.

## 5. 밀도 캡핑 알고리즘 설계

### 선택안: full storage + bounded lane query

셀당 agent 저장 상한은 두지 않는다. 저장을 잘라내면 exact leader/AI와 oracle이 깨지고 특정 agent가 영구 누락된다.

각 bounded query는 다음 순서로 실행한다.

1. broad radius에 해당하는 cell offset stencil을 초기화 때 생성한다.
2. 실제 query 위치에서 cell AABB 최소거리와 cell key로 canonical cell 순서를 정한다.
3. 필요한 team/neutral lane만 선택한다.
4. lane마다 독립적인 candidate visit budget `B`를 적용한다.
5. 한 dense cell이 예산을 독점하지 않도록 active cell ranges를 round-robin한다.
6. cell range 시작점은 query ID/cell/lane/tick hash로 회전시켜 영구 기아를 줄인다.
7. candidate는 self/team/radius filter 이전에 budget을 소비한다. 그래야 strict bound가 유지된다.
8. 실제 pair radius를 통과한 후보만 fixed max-heap에 `(distanceSq, AgentId)`로 유지한다.
9. 결과는 canonical key로 정렬해 반환한다.

복잡도는 고정 team 수와 radius stencil에서 query당 `O(B log K)`, 전체 `O(N·B)`다. Grid build는 O(N + cell×lane)다.

### query별 정책

| Query | Budget/keep | 보존 전략 |
|---|---|---|
| Recruit | team별 `BRecruitPerTeam`, team별 `K=1` | 각 team의 nearest를 구한 뒤 전체 `(distanceSq, claimantId)` 최소 선택 |
| Combat | enemy team별 `BCombatPerEnemyTeam`, `K=min(B, PairNormalizer)` | team이 다른 team을 가리지 않게 quota 분리; fixed edge slot 후 sort/unique |
| Separation | own-team `BSeparation`, 초기 `K=B` | 별도 top-K truncation 없이 budget만 의미 변경 원인으로 제한 |
| Leader | cap 없음 | 현재 최대 4명이라 exact scan도 O(N); escort/killer 의미 보존 |
| Rival AI | cap 없음 | 현재 최대 3명, 0.4초 주기라 amortized O(N); neutral 방향 합 exact 유지 |

현재 asset의 `PairNormalizer=15`는 combat strength가 그 지점에서 포화하는 기존 규칙에서 나온 값이다. rebase 후 재확인한다. 다른 B/K 값은 M-sim-0 전에는 근거가 없어 미확정이다.

### combat edge와 victim 처리

- 각 agent/enemy-team/K에 고정 contact slot을 둔다.
- 양쪽 query 중 한쪽만 pair를 발견해도 edge를 보존한다.
- `(minId,maxId)` sort/unique로 중복을 한 번만 센다.
- team-pair contact count는 기존 `PairNormalizer`에서 saturating add한다.
- victim winner는 기존처럼 strict-larger team 중 최근접, 거리 동률은 낮은 team ID다.
- rate-limited victim 선택:
  - `emitK = min(floor(accumulator[pair]), victimCount)`
  - 작은 K: bounded max-heap으로 정확한 top-K
  - 큰 K: deterministic fixed-pass radix
- instant mode는 모든 victim을 radix로 정렬한다.
- 출력 순서는 기존 pair 순서와 `(distanceSq, AgentId)`를 유지한다.

### gameplay 의미 훼손 최소화

보장되는 것:

- query 반경 자체를 줄이지 않는다.
- 선택된 후보에는 기존 exact pair radius를 그대로 적용한다.
- false positive recruit/combat은 만들지 않는다.
- team별 quota로 한 team의 밀도가 다른 team을 가리지 않게 한다.
- 모든 neutral/non-neutral을 매 tick query한다.
- 회전 cursor로 같은 overflow agent가 영구 배제되는 문제를 줄인다.
- cap 미발동 시 기존 규칙과 같은 결과를 요구한다.

보장할 수 없는 것:

- 임의 개수 agent가 같은 위치/lane에 겹칠 수 있는 모델에서 finite B와 “모든 실제 접촉을 같은 tick에 정확히 판정”은 동시에 만족할 수 없다.
- cap-hit 시 nearest claimant/contact가 누락되어 recruitment/conversion이 지연되거나 separation 방향이 달라질 수 있다.

따라서 cap은 명시적인 bounded approximation이다. 모든 접촉의 즉시 exact 보존이 절대 조건이라면 cap을 포기하고 gameplay occupancy 상한을 강제하거나 별도 exact aggregate/hierarchy 설계로 범위를 변경해야 한다.

### cap 파라미터

M-sim-0 이후 확정할 항목:

- `RecruitCandidateBudgetPerTeam`
- `CombatCandidateBudgetPerEnemyTeam`
- `SeparationCandidateBudget`
- `SeparationKeepCount` — 최초에는 budget과 같게 설정
- cap-hit 허용률
- shadow uncapped query sampling 빈도

`BCombat >= KCombat`, 모든 budget 양수, team 상한을 `OnValidate`/scene validator에서 검증한다.

## 6. 검증 방법론

### 하네스 확장

- full-root profile: 2000/5000 및 가능한 10K
- M2 이후 presentation-free kernel harness: 10K/20K 이상
- 실제 CrowdRoot prefab/SDF ON 경로
- 실제 전체 agent 수 기록
- 동일 seed/count/ticks와 고정 `dt=0.02`
- 독립 프로세스 최소 3회
- A/B는 `A-B-B-A` 순서로 실행
- median, p95, paired ratio와 95% CI 기록
- CPU, Unity/Burst 버전, worker 수, build hash 기록

현재 성능 수치는 없으므로 모든 예상 이득은 외삽이다. “대폭 감소”의 최종 수치는 M-sim-0 A/A noise와 목표 디바이스 SimTick budget을 근거로 승인한 뒤 고정한다.

### 알고리즘 gate

- `CandidatesVisited <= QueryCount × LaneCount × B`
- 2000/5000+에서 candidate work/N이 density 증가에 따라 증가하지 않음
- victim 경로에서 v² comparison 제거
- cap-off/cap-unhit fixture는 reference와 동일
- cap-hit 여부와 skipped broad-phase entry 수 telemetry
- combat directed/unique/duplicate edge 및 pair saturation 기록

### 거동 A/B

Critical fixture는 100% 보존한다.

- recruit nearest/AgentId tie-break
- strict-larger team만 승리
- equal team no conversion
- pair accumulator/emit 순서
- leader escort immunity
- leader killer count/tie-break
- radius 밖 false contact 0
- instant/rate-limit 양 모드
- insertion/grid build permutation

Dense statistical A/B는 다음을 기록한다.

- 최초 접촉 대비 recruit 지연 tick
- claimant/team mismatch
- combat pre-saturation contact deficit
- tick별 conversion 수
- victim/leader elimination team 및 tick
- team-count time series와 최종 winner
- separation angle/magnitude delta
- position/velocity의 p50/p95/max 편차

허용 임계치는 M-sim-0 결과와 실제 gameplay 영상 비교 후 승인한다. 근거 없는 수치를 지금 고정하지 않는다.

### 결정성/oracle

- 모든 scale/seed 조합을 same-seed 2회 비교한다. 현재처럼 첫 조합만 비교하지 않는다.
- 최초 divergence tick과 필드 diff를 출력한다.
- worker/batch permutation 전체를 비교한다.
- event transcript와 RNG/internal state도 byte oracle에 포함한다.

### GC/무할당/lifetime

- warmup 뒤 지원되는 Unity API에서 `GC.GetAllocatedBytesForCurrentThread()`로 1000 ticks delta 0을 요구한다.
- Development Player에서는 `ProfilerRecorder` GC allocation counter로 300 frame 이상 연속 0을 교차 확인한다.
- 현재 `GC.GetTotalMemory(false)` delta는 참고치로만 유지한다.
- `Initialize → ticks → Shutdown` 반복 테스트:
  - 모든 handle Complete
  - 모든 Native 컨테이너 `IsCreated == false`
  - 중복 Shutdown 안전
  - Native leak detection 로그 0
- `GC.GetAllocatedBytesForCurrentThread()`의 현 Unity compatibility는 컴파일 gate에서 확인한다.

### 최종 성능 gate

- 각 단계 개선의 paired 95% CI가 A/A 노이즈 밴드 밖의 개선 방향이어야 한다.
- 관련 없는 sub-stage는 A/A 등가 밴드 안이어야 한다.
- M-sim-1은 알고리즘 work bound가 hard gate다.
- M-sim-2는 schedule/complete 포함 전체 SimTick 개선이 hard gate다.
- 최종 Player는 목표 디바이스에서 승인된 SimTick/frame budget을 만족해야 한다.
- 절대 ms/fps나 개선 퍼센트는 현재 미실측이므로 확정하지 않는다.

## 7. 리스크 + rebase 노트 (리팩토링이 Crowd/Core+CrowdRoot 전부 건드림)

- 변경 파일: 없음. 이번 작업은 읽기 전용 설계다.
- 현재 리팩토링이 완료되기 전에는 구현하지 않는다. 라인 기반 patch/cherry-pick이 아니라 책임 단위로 rebase한다.
- rebase 직후 다음을 다시 확인한다.
  - `GameplayRoot → CrowdRoot.SimTick` 호출과 tick 순서
  - 이동 전 grid와 post-move grid snapshot 경계
  - AgentId 고유성 및 population slot 안정성
  - team 최대 4 계약
  - 전향 후 grid re-lane 시점
  - SDF/CC fallback 상태

## 8. 합의 후보 (다른 설계자와 맞출 핵심 설계 결정 5~8개)

1. 초선형 후보 방문과 victim v² 정렬을 M-sim-1에서 먼저 제거하고, Burst/멀티스레드는 M-sim-2의 상수배 최적화로 둔다.
2. `CrowdRoot`가 `CrowdSimState`와 모든 Persistent NativeArray lifetime을 소유하며, Native position을 sim authority로 삼는다.
3. Grid는 모든 agent를 canonical cell/lane range에 보존하고, 저장 cap이 아니라 recruit/combat/separation의 query 방문량만 cap한다.
4. Recruit는 team별 nearest, combat은 team별 quota와 fixed edge sort/unique, separation은 own-team bounded query를 사용한다. Leader와 rival AI는 현재 상한에서 exact 유지한다.
5. 병렬 단계는 agent별 fixed slot만 기록하고, grid finalize·combat reduction·victim/leader resolve·commit/event는 canonical 직렬 단계로 둔다.
6. Burst는 `Strict/Standard`, RNG는 stable identity 기반 per-agent/per-team stream을 사용한다. worker schedule이나 shared draw 순서에 의존하지 않는다.
7. M1 cap, M2 RNG/math, M3 SDF는 각각 별도의 behavior 승인과 오라클 재기준선 경계를 가진다. Parallel 결과는 승인된 Burst serial 기준선과 byte-identical이어야 한다.
8. M-sim-0은 live prefab/SDF ON/CC fallback 0을 assertion한 2000/5000+ profile로 다시 측정하며, 최종 성능 수치는 이 baseline과 목표 디바이스 budget 이후에만 확정한다.
