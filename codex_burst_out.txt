## 4. 블로커/전제조건

| 전제조건 | 난이도 | 위험 |
|---|---:|---:|
| `WallField`를 read-only unmanaged view로 분리하고 JobHandle 완료 전 Dispose 금지 | 낮음~중 | 중 |
| `AgentBuffer`의 managed SoA를 persistent `NativeArray` SoA로 전환 | 중 | 높음—Team/leader authoritative state 불일치 가능 |
| 계산과 `Transform/Human` 적용 분리 | 높음 | 높음—tick 순서·표현 동기화 변경 |
| Raycast·공유 RNG를 serial island로 남기거나 SDF/per-agent RNG로 대체 | 중~높음 | 높음—행동과 기존 seed transcript 변경 |
| 결정적 native grid와 canonical neighbor order 정의 | 높음 | 높음—FP 누적 순서가 결정성에 직접 영향 |
| Recruit를 per-index 판정 + 고정 순 compaction으로 변경 | 중 | 중 |
| Combat을 병렬 판정, 고정 reduction/budget/sort/commit 단계로 분리 | 높음 | 높음 |
| SDF 미로드 시 CC fallback을 schedule 이전 main-thread 분기로 유지 | 낮음~중 | 중 |

권장 소유 경계는 `CrowdRoot`가 scheduling과 lifetime을 소유하고, runtime 상태는 persistent Native buffer에 두며, worker는 계산만 수행하고 기존 event publish/commit은 main thread에서 고정 순서로 수행하는 것이다.

## 5. 최종 권고

**C — 지금은 하지 말 것.**  
**근거:** 검증된 800명에서 SimTick은 1.62ms이고 렌더가 상한이며, 예상 절감보다 Native 전환·결정성 보존 비용과 위험이 크고 손익분기 N도 입증되지 않았다.

현재 설정인 2000명에서 target-device render-enabled p95가 실제로 CPU crowd-bound임이 확인될 때만 B로 재평가할 수 있다.

검토는 읽기 전용으로 수행했으며 변경 파일은 없다. Unity 실행이나 실제 Job/Burst 비교 빌드는 수행하지 않아 2000명 성능과 플랫폼 간 bitwise 결정성은 미확인이다.

## 합의 후보

- WallSolver/SDF 자체는 unmanaged view로 분리하면 per-agent Burst Job화할 수 있다.
- CrowdRoot 전체 tick은 managed 상태, Unity 객체, Physics, 공유 RNG 때문에 직접 Job화할 수 없다.
- 800명에서는 프레임타임 실익이 작으며 정확한 crossover N은 현재 자료로 확인할 수 없다.
- 결정성은 고정 이웃 순서, index별 출력, canonical reduction/compaction, 명시적 FP 정책이 있어야 보존된다.
- 현재 구현 착수보다 먼저 SDF-ON 하네스 수정과 2000명 target-player 프로파일이 필요하다.
