역할: AF_CrowdCity Unity crowd 시뮬레이션의 확장 아키텍처를 코드 근거로 평가하는 독립 검증자. (라운드1=800명→"솔버 Burst 무의미(C)", 라운드2=몇십만→"per-agent GameObject 모델 붕괴, 전면 재설계(C)". 사용자가 목표를 다시 정정했다.)

**정정된 목표(이번 평가 기준)**:
- 몇 십만은 포기(비현실적 인정). **실제 타깃 = 모바일(중급 Android/iOS)에서 동시 1만~5만(만 단위) 개체.**
- 사용자 선호 접근: "DOTS 급" 또는 "unsafe struct-array 연산급" + 멀티스레드 + Burst. 즉 둘 중 무엇이 이 코드베이스+모바일 만단위에 맞는지가 핵심.

현 상태(코드로 재확인): agent당 Human prefab clone(GameObject) + ~45 Transform(41 skinned bones) + 개별 SkinnedMeshRenderer + 개별 Animator + baked CharacterController + Human MonoBehaviour. 기본 neutralCount=800. Crowd/Core 커널(AgentBuffer=managed SoA 배열, SpatialGrid/CombatResolver/RecruitResolver=managed class+List)은 순수 C#. WallSolver+SDF(WallField=NativeArray<float>)만 Burst-shaped. neutral 이동 Physics.Raycast, spawn Physics.CheckSphere 잔존. 단일 System.Random. Core asmdef은 이미 Burst/Collections/Mathematics 참조. 프로젝트에 BatchRendererGroup/RenderMeshIndirect/DrawMeshInstanced/LODGroup 0건.

평가 질문(각각 코드 파일:라인 근거, 추측 금지, 확인불가 명시):
1. 모바일 만단위 실효성: 현재 per-agent GameObject/Animator/SkinnedMeshRenderer 모델은 모바일에서 대략 몇 명에 붕괴하나? 만단위 모바일 타깃에서 반드시 바꿔야 하는 축을 우선순위로.
2. **DOTS/ECS vs unsafe NativeArray struct-array(+Burst+IJobParallelFor)** — 이 코드베이스에서 어느 쪽? 각 트레이드오프를 구체 비교: (a) 도입 비용/외부 패키지 의존/모바일 빌드 크기, (b) 기존 Crowd/Core 커널(이미 SoA·WallSolver/SDF Burst-shaped) 재사용도, (c) CLAUDE.md §0.2(DOTS 선도입 경계)·§11.5(프리팹-per-agent mediator 트리)와의 정합/충돌, (d) 결정성 유지 난이도, (e) 유지보수/팀 러닝커브. 어느 쪽이 "최소 변경으로 만단위 도달"인가?
3. 모바일 렌더링: DOTS/array 선택과 무관하게 렌더는 반드시 바꿔야 하나? BatchRendererGroup 또는 Graphics.RenderMeshIndirect + baked vertex animation texture(GPU 애니메이션)가 모바일 GLES3.x/Vulkan에서 실효적인가? Animator·SkinnedMeshRenderer·본 Transform 제거가 필수인가? 만단위 모바일 draw call/대역폭/열 예산 관점.
4. 결정성: 만단위 CPU Job(unsafe array 또는 DOTS) 경로에서 기존 오라클 bit-identical 결정성 계약을 유지할 수 있나(몇십만이 아니라 CPU에 남을 수 있으므로)? 유지 조건(FloatMode, 이웃 순서, RNG 스트림)과 grid/combat/recruit 병렬화 시 canonical order 요구를 구체화.
5. 로드맵: 현재(2000, GameObject) → 만단위 모바일까지 최소 변경 경로. 단계별 마일스톤 + 각 단계 검증 게이트(성능/결정성/이질감). 어느 단계가 CLAUDE.md 규약과 충돌하며 어떻게 문서화 피벗하나.
6. 최종 권고: (1) DOTS냐 unsafe-array냐 명확히 택1, (2) 시뮬 부분 재설계 vs 전면, (3) 모바일 만단위가 현실적으로 달성 가능한 목표인지 + 1~2줄 근거.

조사: rg로 렌더 경로(Human.cs, prefab), 커널, GameConfig, Core asmdef, package manifest 확인. 확인 안 되는 수치는 "확인 불가(외삽)"로 명시.

출력(간결): 질문 1~6 결론 + 코드 근거(파일:라인). 마지막 "합의 후보" 4~6개(다른 검증자와 합의 가능한 핵심 주장).
